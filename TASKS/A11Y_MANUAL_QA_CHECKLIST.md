## 1. 공통 접근성 원칙 (All Screens)

### 1.1 포커스 시각화
- [ ] 모든 버튼/링크에 포커스 상태가 시각적으로 명확한가? (색상, 테두리, 음영 변화 등)
- [ ] 포커스 링이 콘텐츠를 가리지 않는가?

### 1.2 색상 대비
- [ ] 텍스트와 배경의 명도 대비가 WCAG AA 기준 (최소 4.5:1)을 충족하는가?
- [ ] 인포그래픽이나 상태 표시가 색상만으로 구분되지 않는가? (예: 아이콘, 레이블 필수)

### 1.3 텍스트 가독성
- [ ] 모든 텍스트가 선명하고 읽기 쉬운가?
- [ ] 폰트 크기가 최소 12px 이상인가? (모바일 제외)

---

## 2. 키보드 내비게이션 (UC-01~05)

### 2.1 SCR-001 메인 페이지
- [ ] **UC-01**: Tab을 눌러 "검색 Hero"의 입력 필드, "조건 정리하기" 버튼까지 도달하는가?
- [ ] **UC-02**: 여행지 Card를 Tab으로 순회할 수 있는가? (국내·해외 그리드)
- [ ] "대표 이야기 더 보기" 링크에 도달할 수 있는가?
- [ ] Enter/Space로 버튼을 활성화할 수 있는가?
- [ ] Shift+Tab으로 역순 이동이 가능한가?

### 2.2 SCR-002 대표 소개 페이지
- [ ] **UC-03**: 프로필 섹션, 통계 영역, 사진 갤러리를 Tab으로 순회할 수 있는가?
- [ ] 링크와 버튼이 모두 Tab으로 접근 가능한가?

### 2.3 SCR-003 여행 도구
- [ ] **UC-04**: 항공편/숙소/동행 탭을 Arrow Key로 전환할 수 있는가? (또는 Tab)
- [ ] 각 탭 내 입력 필드에 접근 가능한가?
- [ ] "찾기" 버튼을 Tab/Enter로 활성화할 수 있는가?

### 2.4 SCR-004 동행 찾기
- [ ] **UC-05**: 필터 바(국가·지역·기간)를 Tab으로 순회할 수 있는가?
- [ ] 동행 목록의 Card를 Tab으로 순회할 수 있는가?
- [ ] 상세 화면의 "참가 신청" 버튼에 도달 가능한가?

### 2.5 SCR-005 계정
- [ ] 로그인 폼의 입력 필드와 버튼을 모두 Tab으로 접근할 수 있는가?
- [ ] 역할별 탭/섹션을 키보드로 순회할 수 있는가?

---

## 3. 스크린리더 호환성 (UC-06~09)

> 테스트 환경: NVDA (Windows) 또는 JAWS (선택사항)

### 3.1 SCR-001 메인 페이지
- [ ] **UC-06**: "메인 페이지" 또는 유사한 Page Title이 선언되는가?
- [ ] 검색 입력의 라벨이 "검색"으로 읽히는가?
- [ ] 버튼 텍스트("조건 정리하기", "동행 더 보기" 등)가 명확하게 읽히는가?
- [ ] 여행지 Card의 제목과 설명이 구분되어 읽히는가?

### 3.2 SCR-002 대표 소개
- [ ] 프로필 이미지의 alt 텍스트가 있고 의미 있는가?
- [ ] 통계 수치("50회 이상", "30개국 이상")가 텍스트로 선언되는가? (이미지만으로 표현되지 않음)
- [ ] 갤러리 이미지 각각의 alt 텍스트가 있는가?

### 3.3 SCR-003 여행 도구
- [ ] **UC-07**: 항공편/숙소/동행 탭이 Landmark 또는 명확한 레이블로 구분되는가?
- [ ] 비전달 고지("입력값은 서버로 전송되지 않습니다")가 읽히는가?
- [ ] 외부 이동 링크("Google Flights로 이동" 등)의 의도가 명확한가?

### 3.4 SCR-004 동행 찾기
- [ ] **UC-08**: 필터 바의 각 입력이 라벨로 제어되는가? (드롭다운, 텍스트 입력 등)
- [ ] "결과 없음" 또는 "N개 결과" 메시지가 텍스트로 공지되는가?
- [ ] 동행 글의 제목, 작성자, 상태(모집중/모집완료)가 구분되어 읽히는가?

### 3.5 SCR-005 계정
- [ ] **UC-09**: 로그인/가입 폼의 레이블("이메일", "비밀번호")이 입력 필드와 연결되는가?
- [ ] 오류 메시지("이메일 형식이 잘못되었습니다" 등)가 명확하게 공지되는가?
- [ ] 역할 전환(Guest → Member) 시 화면 변화가 선언되는가?

## 4. 에러 처리 및 상태 변화

- [ ] 폼 제출 실패 시 오류 메시지가 읽혀지는가?
- [ ] Toast 알림이 role="status"로 공지되는가?
- [ ] 로딩 상태가 명확하게 표현되는가? (예: "로딩 중" Skeleton or spinner)

## 5. ARIA 속성 검증

- [ ] 모든 대화상자(Dialog)에 role="dialog" 또는 role="alertdialog"가 있는가?
- [ ] 숨겨진 콘텐츠에 aria-hidden="true"가 적절히 설정되는가?
- [ ] 동적 콘텐츠 업데이트 시 aria-live 또는 aria-atomic이 사용되는가?
